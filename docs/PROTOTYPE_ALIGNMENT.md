## 第四轮修订（页眉：两个圆角浮块）

把页眉从「一条通栏的白色矩形」改成「左右两个与底色同色的圆角浮块」，滚动时两块钱
向左、右两个角落缩小滑动。

| 项 | 修订前 | 修订后 |
| --- | --- | --- |
| 页眉容器 | 通栏、`background:#fff`、直角 | 透明、不画底色；左右外边距 −20px 让同色遮罩铺满面板 |
| 两块本体 | 品牌块 + 图标块，无背景 | 各自是一个圆角胶囊（`border-radius:23px`、`background:var(--pro-canvas)`、轻投影） |
| 品牌 | `+1` 34px，块 158×47 | `+1` 28px、名称 11px、副标 8px，胶囊 168×46，文字距胶囊左 10px、上 9px |
| 图标 | 22px 图标 / 44px 按钮 | 19px 图标，按钮仍 44px（触控区不变） |
| 页眉总高 | 78px（移动端）/ 72px（桌面） | 62px（两端一致） |
| 滚动后 | 仅字号略缩，容器不变 | 两块 `scale(.8)` + 向左右各平移 6px、向上 2px；`transform-origin` 取外侧上角，视觉上朝角收进去 |
| 内容透出 | 底色 96% 半透明，滚动时内容透出 | 页眉 `::before` 一层同色柔化遮罩（不透明到 76%，再渐隐到 16px 外） |
| 内容穿顶 | 移动端 `top:32px`，滚动时内容从页眉上方穿过 | `top` 由 JS 写入：窗口滚动时避开顶部固定横幅、面板内滚动时为 0 |

实现要点（都是踩过的坑）：

- **sticky 元素越不过父级内容盒上边。** 顶部留白原本挂在 `.page-content.page-home` 的
  `padding-top` 上，页眉贴顶后只能停在内容盒上边，留下一条 10px 的缝让内容露出。
  改成把留白放进页眉自己的 `padding-top`。
- **顶部有一条 `position:fixed` 的验收横幅**（`.review-banner`，z-index 60），页眉贴顶
  会被它压住。`life.js` 把横幅实际高度写进 `--header-sticky-top`，页眉与遮罩都按它让位；
  面板内滚动时该值为 0。
- **只用 transform 缩放**，页眉在文档流里的高度不变，滚动时下方内容不会跳动。
- 遮罩用 `color-mix` 从 `--pro-canvas` 派生半透明档，改底色时只需改一个变量。

自查脚本：

- `verify-header.cjs`：375 / 460 / 1440 三档各测静止与滚动两态，断言容器透明、两块同底色
  且圆角、两块等高、总高 ≤64、触控区达标、贴顶位置正确、滚动后确实变小并向角落移动；
  输出 `verification/header-{375,460,1440}-{top,scrolled,nomask}.png` 与 `header-metrics.json`。
- `verify-header-pixels.py`：像素级复核。取两胶囊之间的间隙（避开投影）× 页眉顶端到胶囊
  下沿那片区域，断言「开遮罩时整片仍是底色」，并用「关掉遮罩的对照张」断言「同片区域确实
  被内容顶出来」——两个断言同时成立才说明遮罩真的在挡内容。

## 第五轮修订（页眉无边框 / 时间轴图标 / 卡片右上角切换）

| 项 | 修订前 | 修订后 |
| --- | --- | --- |
| 页眉本体 | 左右两个同底色圆角胶囊，中间留出的一段空隙把页眉切成两块 | 全部去掉底色、圆角、描边与投影，直接坐在页面底色上；左右内容各自贴页面留白（20px），中间自然留白 |
| 滚动收拢 | 两块 `scale(.8)` 并带投影加深 | 保留 `scale(.8)` + 向两侧各平移 6px、向上 2px，不再有投影变化 |
| 时间轴入口 | 首页页眉右侧是一颗**铃铛** | 换成时间轴图标（竖轴 + 三个节点 + 刻度），与底部导航、我的页菜单共用同一个 glyph |
| 卡片切换入口 | 卡片上方一行「卡片 / 照片版 / 简洁版」分段按钮 | 卡片**右上角**一个双箭头（⇄）小圆钮，44px 触控区，图标下有 30px 半透明白圆底 |
| 切换动画 | 点一下整页 `render()` 重绘 | 轨道里同时放新旧两张卡，`translateX(∓100%)` 横向滑动 420ms，结束后移除旧卡（`prefers-reduced-motion` 时即时切换，同样不重绘） |
| 问候行 | 只在简洁版显示，属于切换内容的一部分 | 常驻显示，不参与切换 |
| 卡片高度 | 照片版 196px、简洁版 168px | 统一 196px（滑轨需要两张卡等高，否则收尾会跳一下） |

实现要点：

- **卡片外层负责裁切，卡片自己不留圆角与投影**：`.banner-wrap{overflow:hidden; border-radius; box-shadow}`
  → `.banner-track{display:flex}` → `.banner-slide{flex:0 0 100%; display:flex}`
  → `.banner-wrap .banner-slide .life-banner{flex:1; min-height:196px; border-radius:0; box-shadow:none}`。
  选择器写到三层才压得住 `.life-banner.style-classic` 的 `min-height:168px`（同优先级时后者靠后胜出）。
- **切换按钮不能塞进卡片里**：卡片本身是个 `<button data-go="numbers">`，按钮里套按钮是非法
  HTML，点击也会串。所以按钮作为 `.banner-wrap` 的绝对定位兄弟节点，浮在卡片右上角。
- **方向可辨**：照片版 → 简洁版时新卡追加在轨道末尾（向左滑出，新卡从右侧进）；
  反向时把新卡 prepend 并把轨道先瞬移到 `-100%`，再动画回 0（从左侧进）。
- 旧卡滑动期间加 `inert`，避免可以被 Tab 到或重复点击。
- 无边框之后，页眉不再靠"框"来分隔页面，**遮罩（`::before` 同色渐变）成为唯一的遮挡手段**，
  这也是"内容不透过页眉"能成立的原因；像素级对照测试继续覆盖这一点。

自查脚本变化：

- `verify-header.cjs`：断言从「两块同底色 + 圆角」改为「底色透明、`border-radius:0`、
  `box-shadow:none`、`border-width:0`」，并新增「页眉的时间轴图标应与底部导航一致且是竖轴 glyph」。
- `verify-home-cards.cjs`：新增切换入口断言（位于卡片内、距右上角 ≤14px、双箭头 = 2 段、
  触控区 ≥44px、有小圆底）与横向滑动断言（滑动中轨道内 2 张卡、轨道 transform 非零、
  外层 `overflow:hidden`、两张卡等高、结束后只剩 1 张卡）；并用 DOM 探针证明切换过程中
  问候行与六宫格**没有被重绘**（不是整页刷新）。

## 第六轮修订（首页卡片回到 codex 的「人生天数」口径）

| 项 | 修订前 | 修订后 |
| --- | --- | --- |
| 卡片首行 | 照片版「已经和这个世界相遇了」、简洁版「你已经生活了」（兜底时都是「你已经收藏了」） | 两版统一「你已经生活了」，兜底「你已经收藏了」 |
| 卡片大数字 | 示例数据没有生日 → 退回记录条数，显示「4 个瞬间」 | 示例数据带生日 → 「11,140 天」（与 codex 原型图一致） |
| +1 徽标 | 只有简洁版有（照片版 `display:none`） | 两版都有，同款白胶囊 + 蓝字 |
| 落款 | 只有简洁版有 | 两版都有；照片版白色斜体，简洁版灰蓝斜体 |
| 结语 | 照片版固定「继续出发，去体验更多可能。」 | 两版统一「仍有很多值得 +1 的瞬间，在路上。」 |

实现要点：

- **文案只有一份**：抽出 `bannerCopy()` 产出 `{label, count, unit, note}`，两种版本共用；
  `bannerCard(style)` 只决定 class（`style-classic` 与否）。以后改文案只改一处。
- **单位包一层 `<span class="banner-unit">`**：原来单位是裸文本节点，脚本没法稳定取到，
  包起来后断言可以精确比对「天 / 个瞬间」。
- **示例数据的人物生日 `DEMO_BIRTHDAY = '1996-03-19'`**：按原型图的 11,140 天反推，
  保证验收时看到的数字与 codex 原型图一致（会随日期自然增长）。
- **老示例数据的迁移**：旧版存在浏览器里的示例数据生日是空的，会让卡片退回「收藏了多少个
  瞬间」。加载时若满足「`demo:true` + 没有生日 + 记录非空 + 记录全是示例那几条」，就补上生日
  并写回；**只要用户自己加过记录或填过生日，一律不动**（避免凭空替真人编造生日）。

自查脚本变化：

- `verify-home-cards.cjs`：断言「照片版不显示落款 / 徽标」改为「两版都显示落款与 +1 徽标」，
  新增「首行 = 你已经生活了、单位 = 天、结语 = 仍有很多值得 +1 的瞬间，在路上。」、
  「大数字是带千分位的天数且 > 10000」、「两版内容逐字段相等（只换视觉不换文案）」，
  以及一条**迁移回归**：把老格式（生日为空）的示例数据写进 localStorage 后重载，
  断言卡片自动回到天数口径。

## 第七轮修订（两版各说一件事 + 字体格式对齐）

第六轮理解偏了：当时把两种卡片当成「同样内容、只换视觉」，于是两版都改成了人生天数。
实际设计是**两版各说一件事**，且**字体格式必须一致**。

| 项 | 第六轮（错） | 第七轮（对） |
| --- | --- | --- |
| 照片版 | 你已经生活了 N 天 | **你已经收藏了 N 个瞬间** + 继续出发，去体验更多可能。（不带 +1 徽标与落款） |
| 简洁版 | 你已经生活了 N 天（与照片版内容相同） | **你已经生活了 N 天** + 仍有很多值得 +1 的瞬间，在路上。+ `+1` 徽标 + 落款 |
| 数字字号 | 照片版 46px/700、简洁版 42px/600 | **两版都是 46px / 700** |
| 首行字号 | 照片版 13px、简洁版 12px | **两版都是 13px/20px** |
| 单位字号 | 两版都是 15px/22px/600 | 不变 |
| 结语字号 | 照片版 13px/20px、简洁版 11px/17px | **两版都是 13px/20px** |

实现要点：

- `bannerCopy(style)` 现在**按版本给不同内容**：`classic` 且填了生日 → 天数口径；
  其余（照片版、简洁版未填生日）→ 收藏瞬间口径。徽标与落款由 `badge` / `caption` 两个
  布尔位控制，只有天数卡渲染它们。
- **简洁版只允许覆盖颜色，不许覆盖字号**：`.life-banner.style-classic .banner-copy*` 一组规则
  里原先带着 `font:` 简写（12px / 42px / 11px），会整体比照片版小一档，已全部删掉只留 `color`。
  在 `.banner-copy` 基础块上方留了注释说明这条约定。
- 字号来源本就是 `prototype.css`（最后加载）压过 `life.css` / `experience.css` 的
  `42px / 12px / 11px` 一组值，所以只要不在这里继续写简写，两版就自动同档。

自查脚本变化（`verify-home-cards.cjs`）：

- 新增**字体格式指纹**：对「首行 / 大数字 / 单位 / 结语」四段分别取
  `fontSize | lineHeight | fontWeight | fontStyle | fontFamily`，断言两版 `deepEqual`。
  以后谁再给某一版单独调字号，这条会立刻红。
- 断言反过来：照片版必须是 `你已经收藏了 / 个瞬间 / 继续出发，去体验更多可能。`
  且**不带** +1 徽标与落款；简洁版必须是 `你已经生活了 / 天 / 仍有很多值得 +1 的瞬间，在路上。`
  且**带**徽标与落款；两版的单位与大数字必须不同（证明内容确实是两套口径）。
- 迁移回归那条改成先切到简洁版再断言（默认进的是照片版收藏卡）。

## 第八轮修订（文字到卡片边缘的距离统一 + 落款并入排版系统）

反馈：「字体距离卡片边缘的距离不一致，天数卡片要和瞬间卡片保持一致，而且字体格式和大小感觉还有差异」。

逐项量下来，**正文四段的几何两版早就一致**（左上右下都是 20 / 20，字号行高字重字体族只差颜色），
真正的差异只有一处：**天数卡右下角的落款「A More Colorful Life」**。

| 项 | 修改前 | 修改后 |
| --- | --- | --- |
| 落款右边距 | `16px`（正文是 20px） | `20px` = `--pro-inset` |
| 落款下边距 | `14px` | `calc(--pro-inset + 15.7px)`，把倾斜下沉量补掉（见下） |
| 落款字体 | `italic 13px Georgia, serif` | `italic 13px/20px var(--font-ui)`（与结语同字号、同行高、同字体族，只保留斜体） |
| 卡片左右内边距 | 三处各写一个 `20px` | 统一走 `--pro-inset: 20px` |
| 落款旋转轴 | 默认中心 | `transform-origin: right bottom`（绕着右下角转，右端的 20px 不会因倾斜漂移） |

也就是说：一张卡里唯一一个「自带一套边距 + 自带一套字体」的元素被收回了排版系统。
肉眼看到的就是落款比正文更贴边、字形也不一样 —— 去掉这两处例外，两版的距离就是同一套数字。

**倾斜补偿这一笔**：落款绕右下角转 `-7°`，左端会跟着下沉「宽度 × sin 7°」。
`A More Colorful Life` 在 13px 斜体下宽 128.8px → 下沉 15.7px。
只写 `bottom: 20px` 时，量未旋转的盒子是 20px，但**眼睛看到的左端只剩 4.3px**，
这正是「看着比正文更贴边」的来源。所以把下沉量补进 `bottom`：
`bottom: calc(var(--pro-inset) + 15.7px)` —— 旋转后整块墨迹的最低点才落在距卡片底 20px 的线上。

在**用户自己那两张截图**上实测对照（旧版 vs 这一版，按模板匹配反推卡片框后换算成 CSS px）：

| 落款可见距离 | 用户截图里的旧版 | 这一版 |
| --- | --- | --- |
| 右端 → 卡片右边 | 18.4px（16px + 倾斜偏移） | **20.0px** |
| 最低点 → 卡片底边 | **4.3px（几乎贴边）** | **20.0px** |

同一张截图里量到的**正文四行**则是：距卡片左 `20.0 / 24.0 / 20.0`、距卡片上 `50.4 / 80.8 / 138.4`，
与当前渲染逐项相同（`24.0` 是数字行——大数字首字符的字形侧边距）。也就是说正文一直是齐的，
用户看到的「歪」是落款这一处造成的。

自查脚本变化（`verify-home-cards.cjs`）：

- 新增 `edgeOf()`：先临时清掉 `transform` 再量 `getBoundingClientRect`，拿到未旋转的盒子几何。
- 新增 `rotatedQuad()`：按 `transform-origin` 把盒子的四个角真的转一遍，算**旋转后**的四边形。
  落款是斜的，只量未旋转的盒子会漏掉那 15.7px 的下沉 —— 也就是「量着对、看着不对」。
- 新增**边缘距离断言**：对「正文整体 / 首行 / 数字行 / 结语」四段分别取到卡片四边的距离，
  先断言两版逐项 `deepEqual`，再断言左右都等于 `--pro-inset`（20px）。
  首行 `<span>` 是行内元素、盒子宽度跟着文字走，只比对 `left / top`。
- 新增**落款断言**：旋转后右端距右边 20px、最低点距底边 20px（±0.5px），
  字号 / 行高 / 字体族必须等于照片版结语的三个值（允许斜体）；375 视口下同样再断言一遍。
- 以后谁再给某段文字单独写 `padding` / `margin` / 字体 / 旋转，这几条会立刻红。

### 3. 修掉一个真 bug：HTML `hidden` 属性失效

写上面第 4 组断言（「第一次」不评分，评分字段应隐藏）时暴露出来的：

```
prototype.css 的 `.field { display: flex }` 覆盖了浏览器自带的 `[hidden] { display: none }`
→ experience.js L54 写的 `hidden` 属性名存实亡
→ 选「第一次」「去过的地方」这些**不评分**的分类时，评分下拉照样显示在表单里
```

实测：初始 `hidden=true` 但 `display: flex`、盒子高 72px；切到「美食」去掉 hidden 后反而看不出区别
—— 也就是说这个字段一直是常驻显示的。

修复：在 `prototype.css` 的 `.field` 之前补一条最高优先级的通用兜底：

```css
[hidden] { display: none !important; }
```

已核查全仓 `hidden` 的其它用法都是显隐切换或 `aria-hidden`（不匹配 `[hidden]`），无副作用。
