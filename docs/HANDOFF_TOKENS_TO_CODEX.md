## 一、你接手的是什么

WorkBuddy 这一轮做的是**收敛**，不是重设计：

| 做了 | 没做 |
| --- | --- |
| 五套变量体系 → 一套 `tokens.css` | ❌ 没有重新设计任何页面 |
| 新增 `components.css` 统一跨页组件 | ❌ 没有改首页视觉（像素级零变化，已验证） |
| 旧变量名做成过渡别名，调用点零改动 | ❌ 没有清理完所有残留硬编码色值 |
| 新增 `verify-tokens.cjs` 守卫 | ❌ 没有提升各页面的精致度 |

**所以「其他页面还是粗糙简陋」这个需求只完成了一半**：地基平了，还没装修。
剩下的是排版节奏、层次、留白、组件细节的打磨——这部分是你的活。

## 二、硬红线（违反会被守卫拦住）

1. **取值只能写在 `tokens.css`。** 其它任何 `.css` 里不允许出现
   `--xxx: <具体值>`。要加令牌就加到 `tokens.css`。
2. **组件里不写死颜色。** 一律 `var(--color-*)`。新颜色必须先在 `tokens.css` 登记。
3. **不要替换两个品牌蓝**：
   - `--color-brand` `#3286ee`（codex 原 logo 蓝）
   - `--color-brand-bright` `#3a8cf7`（主按钮 / chip 选中 / 图标容器）
   两者差 8/6/9，**不可互换**，理由见 `tokens.css` 第 1 节注释。
4. **新增样式/脚本文件必须登记进 `serve.cjs` 的 allowlist**（文件顶部那个 `Set`）。
   **样式表 404 不报错**，只是整份静默失效、页面看起来正常但变量全空——本轮就栽在这上面，
   查了好几轮才发现。`verify-tokens.cjs` 现在有专门断言拦这个。
5. **`.git` 不要放在同步盘**或同步期间做 git 写操作（会丢 `refs/heads/*` 引用文件）。
   push 用 `.workbuddy/push-via-api.cjs`（公司网络封 `github.com`，走 Git Data API）。
6. **改完必跑守卫**：
   ```bash
   node serve.cjs &              # 端口 4186
   node verify-tokens.cjs        # 令牌守卫：42 令牌 / 7 路由一致性 / 野颜色
   ```
   再跑全套 9 个脚本（清单见 `docs/DESIGN_TOKENS.md` 第七节）。

## 三、当前已知的「还没清干净」清单（你的第一批活）

守卫报「0 野颜色」是因为它的扫描范围只覆盖 `.page-content *`、`.bottom-nav *`、
`.app-header *`（`verify-tokens.cjs` 里 `scanColors()` 的选择器）——**首页 hero 装饰区不在扫描内**。
这些是真实的残留（已排除注释行）：

| 文件 | 残留色值 | 去重后 | 性质 |
| --- | --- | --- | --- |
| `life.css` | 57 处 | **57 个** | 去重后数量不变 = **每个值只用一次**，是一次性浅色/半透明装饰（`#f9fdffe8`、`#eff9ff88`、`rgba(243,250,255,.88)`…） |
| `experience.css` | 29 处 | 25 个 | 同上，以中低透明度浅蓝为主 |
| `prototype.css` | 15 处（含注释） | **10 个生效** | `#fff`（`.banner-copy`、`.bottom-nav` 底色）、`#f6faff`/`#eaf3fe`/`#dfeefb`/`#dceafb`（卡片渐变）、`rgba(8,22,42,.9/.95/.55)`（落款光晕）、`rgba(255,255,255,.8/.95)`（落款微光） |
| `tokens.css` | 79 处 | — | **这是正常的**，令牌定义本体 |

> 注：`prototype.css` 里出现的 `#6a7d92` 只在**注释**中（落款选色的历史记录），
> 实际生效的落款色已经是 `var(--color-ink-4)`（`#6a7d92` 同值）。排查时注意别被注释误导。

**建议处理方式**：不要一次性盲扫替换。这些值大多是一次性装饰，
归并成令牌需要判断「是否会在第二处用到」（规约第 2 条）。
推荐顺序：

1. **先收 `prototype.css` 那 10 个**：`#fff` → `var(--color-on-dark)` / `var(--color-surface)`，
   卡片渐变 4 个浅蓝 → 归纳 2~3 档，落款光晕/微光 → 现有 `--scrim-deep` 系 + `--color-on-dark-*`。
   这 10 处都能直接对应到已有令牌，是低风险的干净起点。
2. **再扩守卫扫描范围**，把首页 hero 装饰区纳入（`verify-tokens.cjs` 的 `scanColors()`
   里那个 `querySelectorAll` 选择器，约在第 62 行），让它替你把剩下的抓出来——
   **先有尺子再动手**，否则清不干净也测不出。
3. **最后按需归并 `life.css`（57 个）/`experience.css`（25 个）的浅色族**。
   这一族的麻烦在于**值几乎不重复**（57 处就是 57 个不同值），提示它们是随手调的，
   不是有意图的色阶。建议归纳成 3~5 档
   （如「近白卡片底 / 浅蓝雾 / 半透明白」），同一档内部允许 ±2 的色差——
   **不要为这 82 个值建 82 个令牌**，那只是把硬编码搬了个家。

## 五、可复用的方法论（这轮最有价值的部分）

**「量取已验收页面」而不是「另起设计稿」。**

首页是用户验收过的。WorkBuddy 的做法是写一个 Playwright 脚本把它的 computed style
全量量出来，**量出来的值就是规范**——令牌不是发明的，是被批准的。
脚本原本在 `.workbuddy/probe-home.cjs`（已删，需要时照 `verify-tokens.cjs` 的
`page.evaluate` 写法重写一个，思路见下）。

**为什么这招好用**：另起设计稿一定会和已验收的首页打架，然后得回头改首页（返工）。
量取法天然自洽，且能声称「视觉零变化」并且**证明它**（首页像素校验脚本前后数字完全一致）。

**给其他页面对齐时同理**：先跑一遍量出现状 → 和首页基线对比 → 差异处按令牌收敛。

**两个技术坑**（写测量脚本会踩）：
- `getPropertyValue('--x')` 对**别名**返回的是「替换后但未计算」的声明值
  （`var(--pro-canvas)` 返回 `#eef4fd`），**不是**计算值。
  要拿真实渲染值，得建个探针元素 `d.style.color = 'var(--x)'` 再读 `getComputedStyle(d).color`。
- 颜色比较要先归一化：声明 `rgba(255,255,255,.88)` vs 计算 `rgba(255, 255, 255, 0.88)`
  ——去空白 + 补前导零才能做集合比较。
